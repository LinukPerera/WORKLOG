## PaliVerse RAG — passage-linking benchmark finished and spot-checked, a new related-passages program built, regression demo re-run — 4 hours (10:30–14:30), plus an untimed addendum

Source: `mini_rag/WORKLOG.MD`, referred to here as "PaliVerse RAG"

**The passage-linking benchmark left running since 2026-11-06 finished overnight. Real final
result**: **16,962 / 25,975 = 65.3% top-5 recovery**, 27,709.3s elapsed. Lower than the original
chapter-1-only baseline (79.73%), but not a clean apples-to-apples comparison — that baseline
was 148 links from one discourse; this is 25,975 links across the whole canon's real structural
diversity. One real pattern found in the misses: several consecutive root units sharing a
single commentary unit all failed to recover it — when one commentary passage explains many
root units at once, embedding similarity struggles to rank it top-5 for every one of them
individually.

**Built `find_related_passages.py`** — the first concrete step toward wiring this project's
retrieval into info-tab generation: given a unit, pulls genuinely related content from anywhere
in the full canon via pure embedding similarity, zero new API cost. Ran it on 3 sample units,
saved the output to a report for review.

**Manually checked the program's output by reading the full passages, not just trusting the
distance score and snippet — found a real overclaim and corrected it.** Of two cross-text
connections the program surfaced, one held up as genuinely strong on a full read (near-verbatim
shared text between two units); the other did **not** hold up — the full text showed it only
shares a stock narrative convention (a recurring assembly-scene formula), not the actual theme
of either passage. Corrected the report rather than let the overclaim stand. Real lesson
recorded for the info-tab integration this is building toward: a low distance score is
necessary but not sufficient for a connection to actually be useful — spot-check the real
content, don't trust the number alone.

**Re-ran the original 6-question chapter-1 demo set** against the retrieval fix made on
2026-11-06, to close the regression-test gap flagged that day (the fix changed retrieval
behavior for every query, not just the ones tested then). Ran much slower than before — real
concurrent load contention confirmed directly on the server (the demo and the
`find_related_passages.py` samples were hitting the same small server at the same time). Still
in progress at the 14:30 cutoff — left running unattended, same pattern as the benchmark run on
2026-11-06.

**Real cost consequence of that pattern, found and flagged, not hidden**: the benchmark run left
going from 2026-11-06 to today is the direct reason this project's month-to-date Azure spend
jumped from €0.36 to **€13.44** — the server was never stopped after the benchmark finished,
confirmed via the project's own cost-check script run this morning. Doing the same again today
with the demo re-run, consciously, because killing an in-progress run mid-way would waste real
work and give no regression result at all — but flagging the pattern so it doesn't become a
habit.

**Addendum, after the 14:30 close**: asked to manually validate the two cross-text connections
mentioned above by reading the full passages rather than trusting distance + snippet alone —
this is the same correction already folded into the write-up above (the program's two flagged
connections, one confirmed strong, one corrected).

## LogPrompts Research (Alpha-Log-Probs) — a confusion-matrix program built for Shindan profile 17, a team briefing written, local docs-hub instance stood up — 5.5 hours (15:30–21:00)

Source: pulled from the `Alpha-Log-Probs` GitHub repo (`worklog.md`).

**Built `p17_our_confusion.py`** — computes confusion counts (true/false positives and
negatives) per MQM category for both DeepSeek and Gemma, for two of this project's own tests
(the confidence-score rule at its chosen cut-off, and the 700-finding Yes/No judge sample),
using Alpha's own Shindan-alone result as the benchmark to compare against. Output saved to a
results table.
- Real result (DeepSeek, confidence rule, representative rows): Meaning kept 1,630 of 3,568
  findings as true positives against Alpha's own 1,908, at a cost of more false negatives (278
  vs. Alpha's 0, since Alpha's own run keeps every finding); Glossary and Format moved the
  numbers least, consistent with the earlier finding that those two categories carry no real
  signal.
- Real result (the 700-finding Yes/No judge, DeepSeek): the judge agreed with the human raters
  most often on Punctuation (47 correct of 50 confirmed-real cases) and least on Format (40 of
  50), with Style scoring a clean 50/50 — no false negatives at all in that one category's
  sample.

**Checked the team meeting's stated conclusion directly against the data, rather than taking it
at face value.** The meeting concluded Completeness, Glossary, and Format are all useful
categories for this approach. Checked each one's actual AUC with confidence intervals on both
the cutoff half and the test half: **only Completeness holds up in both halves** (0.581 and
0.603, both above chance with a real margin); Glossary shows no signal in either half; Format
flips between the two halves and is too thin a sample to trust either way. **The meeting's
conclusion is not supported by this project's own data, nor by Alpha's own report** — flagged
directly rather than let stand.
