**Removed a text from the RAG on client instruction — checked the real structural situation
first rather than assume it was a standalone text to delete.** It isn't one: no source file for
it exists anywhere in the corpus. What actually exists is 23 incidental *citations* of it,
embedded inside genuinely canonical commentary across 18 different files — real classical
commentarial practice (a commentary explaining a point by citing an older, related text), not
an external modern reference. Deleting the underlying commentary text would have destroyed
genuine canonical content over an incidental citation inside it — the real fix was narrower:
removed only the embedding row for exactly those 23 chunk IDs (making them unreachable by every
search/KNN function in the project, since all of them join chunk to embedding), while leaving
the chunk row and its content intact as a provenance record, not destroyed. Also tagged those
rows `consumer_scope='internal'` (an existing column value, not invented) and appended a dated
provenance note to each, so the exclusion is auditable at the database level, not just
inferable from a missing embedding. **Known residual, disclosed rather than hidden**: an
existing canon-wide connections report built before this exclusion may still list one or more
of these 23 as a candidate elsewhere — confirming that precisely would need re-deriving from
raw data, flagged rather than silently assumed clean.

**Built the entity-linking (shared-rare-proper-noun) connection-finding method** and swept its

**Built an HNSW index to fix a real, severe performance problem** — pgvector's own HNSW index
has a hard 2000-dimension ceiling, worked around with a halfvec cast on the embedding column:
**26s → 0.21s per nearest-neighbour query, roughly 120x**. Added a fast-candidates helper and
routed every script through it. Profiled and fixed two further real bottlenecks (batching
per-candidate queries instead of issuing one at a time; memoizing the proper-noun extraction
step) — **47.8s/unit → 4.0s/unit, roughly 12x combined** on top of the index fix.
