## Agent Unit Explanations — pilot revised and caught a real accuracy bug, the full 149-unit cross-canon run generated and spot-checked, a second real regression found and hand-fixed — 9 hours (10:30–19:30)

Source: `agent-unit-explanations/WORKLOG.MD`

**Revised the pilot batch per review request**: switched from the sequential units 1-5 to unit
1 plus 4 random units scattered across the chapter (9, 35, 67, 87), and capped the
preceding-units-in-chapter block to the last 5 units instead of carrying every earlier one.

**Ran the 5 revised pilot prompts live and found a real accuracy bug by comparing against the
already-delivered October version**: both versions said a figure "abuses" the Buddha, but the
real root text only ever says he "spoke in many ways in dispraise of" him — "abused" overstates
what the source actually says. Added a new rule to the project's storyteller rules (characterise
the text with the word it actually uses, not a stronger or weaker one of the model's own
choosing), regenerated the same 5 units, and confirmed the overstatement was gone and the fix
applied with real judgment, not blanket suppression — one unit now explicitly distinguishes
"not raw abuse but argument... the text says he spoke in dispraise."

**Investigated a user question about paragraph IDs**: confirmed the database's own
paragraph-ID field already holds the full UUIDs, matching exactly the source database's own
column — the short "¶a78e2ae8…" citation display is just the first 8 hex characters of that
same UUID, truncated for display, not a separate or shortened identifier.

**Ran the real chapter-1 generation, approved only after the revised pilot passed.** Built all
149 augmented prompts as a pure local-file operation, reusing the October run's existing prompts
rather than re-calling the prompt builder — avoided a needless second entity-extraction spend
and preserved the correctly sequential entity ledger that a fresh rebuild would have disturbed.
Generated units 1-5 live first as a final quality gate ($1.1385), then units 6-149 via the Batch
API (121s, 144/144 succeeded, $10.4655). **Total: 149/149 succeeded, $11.60 real cost.**

**Random-sampled the completed run for consistency**: a full structural sweep (headers, word
counts, no truncation), a corpus-wide sweep specifically for the word "abuse" (4 hits found, all
checked and confirmed legitimate uses this time), a deep read of 5 random units, and confirmed
the entity ledger and the preceding-units window both stay correct all the way through to unit
149.

**User asked to compare a few units against their old versions by hand — found one more real
issue.** Read 6 specific units in full against their October versions, then swept all 149 units
for other "loaded" words beyond "abuse" (attack, condemn, insult, mock, scorn, rebuke, cruel,
wicked, evil, lying). Found one genuine new regression: one unit escalated the source's
consistently-repeated "not proper" into "what the passage is condemning" — the same class of
overstatement error as the original "abuse" bug. Everything else checked was either the model
correctly declining an escalated characterisation (a good sign, the same pattern as the earlier
fix working as intended) or interpretive language that was already present in the October
version too, not a new regression.

**Checked real evidence before worrying the new rule might over-correct against genuine abuse
elsewhere in the corpus**: two other units already use "abuse" correctly, where the text itself
really does describe mere reviling or names an actual vice — confirming the new rule
discriminates rather than blanket-suppresses the word. Proposed, but did not yet apply, one
added sentence making the opposite (de-escalation) direction explicit too, since every example
written into the rule so far only models the escalation direction.

**Hand-patched the one real regression directly** rather than regenerating the whole unit
("rules improper" in place of the overstated "is condemning").

**Built `combine_chapter1_cross_canon.py`** (same convention as the existing client-combine
script) and produced the full 149-unit combined output file, deliberately kept under its own
distinct name so it's never confused with the already-delivered October version.
