## Agent Unit Explanations — a restricted-sources prompt module built, two real Pali-matching bugs found and fixed — 4 hours (10:30–14:30)

Source: `agent-unit-explanations/WORKLOG.MD`

**New requirement**: at whole-canon scale, a one-chapter batch can't be hand-verified the way
the cross-canon pilot was, so it must use only a unit's own three sources (its own root text,
linked commentary, linked sub-commentary) while still matching the cross-canon batch's richness.

Read the retrieval code directly to find exactly what needs dropping: one existing function is
already correctly scoped to a unit's own hierarchy and could be reused unchanged; two others
reach outside it (one searches the whole chapter's commentary range, one searches anywhere in
the source file) and had to go.

**Built `stages/stage7_prompt_builder_restricted.py`** — a new module (the validated original
prompt builder stays untouched, still the engine behind the richness benchmark): restricted
entity/term-card functions keep only the mechanical exact-citation tier and the glossary
lookup; the restricted prompt builder omits the two out-of-scope search mechanisms entirely.
Re-runs the entity-extraction stage fresh per unit rather than guessing which entries in an
existing rendered prompt came from which source.

**Problem**: testing unit 13 found the fold index defaulted to English only, so Pali terms
identified by entity extraction (e.g. "dhovana," the bone-washing festival) could never be
found even though they appear verbatim in that unit's own Pali-language root text and
sub-commentary — the original builder never hit this gap because its semantic fallback bridged
it by meaning, which the restricted builder deliberately doesn't have. **Fix**: build and check
both an English and a Pali fold index.

**Problem (partial fix)**: even checking both languages, 28 of unit 13's Pali terms still came
back "not found," because Pali inflects and compounds freely, so a dictionary stem never
appears as its own whole word in running text. **Fix**: added a substring fallback scoped
strictly to that one unit's own four text blocks — never reaching any other unit, so it doesn't
reintroduce the whole-word-vs-substring name-collision risk the original whole-word rule was
written to prevent (that risk is about different real entities colliding canon-wide, not one
unit's own inflected vocabulary). Result: unit 13's "not found" count dropped from 28 to 2.

**Generated 4 initial test units live (1, 13, 20, 24) before the substring fix**, for a first
read against the benchmark — mixed (unit 1 exceeded it, unit 13 fell well short before the
Pali-matching fixes landed). Re-testing with both fixes in place is the immediate next step, not
yet complete as of 14:30.

## LogPrompts Research (Alpha-Log-Probs) — a new 5,000-per-pair dataset checked, a pre-registered go/no-go pipeline built and run, final report written — 4 hours (15:30–19:30)

Source: pulled from the `Alpha-Log-Probs` GitHub repo (`worklog.md`).

Aim: check a newly shared Shindan profile 17 dataset, work out what it adds to the earlier
10,000-segment run, plan an analysis that gives a real go/no-go decision, run it, and write the
report.

**Checked the new dataset directly, read-only** (a shared-link sign-in couldn't be completed in
the in-app browser, no credentials entered; the user supplied a local copy instead). Real
contents found: 9 language pairs, 29,483 segments (256 parse failures, 29,227 scored), per-pair
tables, and 592 raw call files with per-token log-probabilities. Confirmed the confusion counts
in every pair's summary add up to the scored total before trusting anything further.

**Built `p17_5000_data_check.py`** — checks the new data against the earlier 10,000-segment
run for overlap. **Found**: 5,058 of the 19,483 new segments share a source sentence with the
earlier set, leaving 14,425 genuinely source-disjoint segments to treat as the real new
evidence.

**Built `p17_5000_labels.py`** — applies the category-to-Shindan-group crosswalk already
learned from the earlier 10,000 segments to the new data. **Found**: it reproduces Alpha's own
flag label exactly on all 32,014 segment-groups tested — the crosswalk itself didn't need
re-deriving.

**Wrote the go/no-go plan** (`GO_NO_GO_PLAN_P17_5000.md`) and got it approved before any new
analysis ran: rules frozen on the earlier 10,000 segments, one single confirmatory test on the
new source-disjoint segments, four questions each with one primary endpoint, fixed controls,
and explicit GO/NO-GO/INCONCLUSIVE rules set in advance.

**Built `p17_5000_freeze.py`** — fits every scoring choice on the earlier 10,000 segments only,
before the new data is touched at all, so nothing can be tuned on the evidence it's about to be
tested against.

**Built `p17_5000_confirmatory.py`** — the real, locked, run-once analysis: random-effects
pooling across all qualifying language pairs, 2,000 cluster bootstraps, a Holm correction across
10 tests, plus the pre-registered controls and three sensitivity checks.

**Built `p17_5000_q3.py`** — tests specifically whether the confidence signal catches real
errors Shindan missed entirely (not just ranks its own flagged findings).

**Wrote the final report** (`GO_NO_GO_P17_5000.md`) and the project handoff doc's own section
for this result.

**Real result, verdict by the rules fixed in advance: INCONCLUSIVE on every question tested.**
The combined score does beat Shindan's own score in all five categories tested (a real,
statistically significant gain) — but the actual reduction in trusted-false-flag share falls
short of the 2-point bar set before the run in four of five categories, and a simple baseline
built only from Shindan's own severity, segment length, and flag count does just as well in
every category — meaning the pre-registered controls did not confirm the log-probability signal
adds anything beyond what's already visible to Shindan itself. The missed-errors question (Q3)
came out similarly inconclusive, not distinguishable from a plain length-based baseline.

**Recommendation written into the report**: do not build a log-probability confidence layer on
this evidence. The final call belongs to the project owner, not made in this session.

**Caveats recorded plainly**: the confirmatory comparison used an equal escalation share per
pair and category rather than the originally frozen cut points; several planned
stratifications and the exploratory token-level signals weren't run; one language pair is
degenerate (Shindan flags 99.6% of its segments, making it uninformative); the shared-copy
dataset wasn't checksummed against the original; this round is DeepSeek-only; and cost,
latency, a second-model escalation stage, and the CometQE/MetricX baselines remain untestable
from this side.
