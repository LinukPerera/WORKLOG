## PaliVerse Segment Edit History Investigation — error pattern catalog: a 3-tier detectability framework — 2.5 hours (10:30–13:00)

Source: `segment-history-db/WORKLOG.md`

Ask: build toward an algorithm that finds errors by category, by generalizing each class's
instances into recurring error patterns, backed by a few good concrete examples of each.

Wrote `ERROR_PATTERN_CATALOG.md`. For every MQM category/subcategory observed in the full run,
pulled real grounded examples (segment ID, original/final text, evidence) from the classified
results and named the recurring sub-pattern each one belongs to — not just "this is a
mistranslation" but the specific *shape* of mistranslation (e.g. formulaic stock-phrase
literalism vs. idiom/collocation literalism vs. unwarranted gender attribution, each with its
own examples).

**Organizing idea**: sorted every named pattern into one of three detectability tiers:
1. **Mechanical** (regex/dictionary, no model call): spelling variants, duplicate-word bugs,
   closed-set discourse-marker swaps, capitalization-only changes, and — the highest-value
   one — a generalized mixed-script boundary-break detector that catches the earlier-found
   bulk-replace bug pattern *and* would generalize to any future bulk-replace making the same
   word-boundary mistake on a different term.
2. **Corpus-wide statistical** (needs the whole corpus as context, still no LLM): terminology
   inconsistency/standardization via a term-consistency-clustering pass, and formulaic-phrase
   mistranslation once the formula is cataloged.
3. **Semantic judgment** (genuinely needs an LLM or a human): real
   mistranslation/ambiguous-rendering idiom cases, sensitivity, source-interpretation.

**Verified a specific worked example** while writing the sensitivity section: re-checked the
"wrinkle-faced one"/"ape" flip found during the original 2026-10-21 DB exploration against the
final classified results. Confirmed two things worth keeping in mind for any future detector:
(1) the segment where "ape" survived to the final text was correctly labeled
mistranslation/addition, not sensitivity — a defensible call given it reads as a zoological
simile in context, illustrating how little surface signal separates the two categories; (2) the
same verse/edit, but reverted within the observed history, shows as "text unchanged" —
confirming a real, structural blind spot: this pipeline only ever compares original-vs-final,
so any edit that was tried and reverted is completely invisible to it. This is the most likely
explanation for zero sensitivity-category detections across all 38,836 segments, rather than
genuine absence.

Cleaned up a 24MB scratch lookup file used only to pull examples for this document — not a
deliverable, deleted rather than committed.

## PaliVerse Segment Edit History Investigation — generalization strategy, pattern dictionary, and a validated detector — 2 hours (18:30–20:30)

Source: `segment-history-db/WORKLOG.md`

Ask: the next step toward an actual detection algorithm — a strategy for generalizing the found
patterns to new (unedited) text, plus more examples in the catalog.

Wrote `GENERALIZATION_STRATEGY.md` and built the artifacts it describes, rather than just
describing the strategy on paper:

1. **Mined a reusable term dictionary**: every recurring before→after pair (count ≥2) from all
   38,836 classified segments, merged across whichever MQM labels they appeared under: 1,976
   entries, a reusable lookup table applicable to any text with no diff required.
2. **Backtested the dictionary** to validate it actually generalizes rather than just
   memorizing its source segments: applied dictionary entries (count ≥3, word-boundary matched)
   to each segment's *original* text and checked whether the *final* text matched the predicted
   fix. Multi-word phrases: 88.5% precision. Single-word entries: 36.4% — a large,
   decision-relevant gap, since it means single-word matches can't be trusted standalone and
   should only trigger a Tier-3 LLM check, never an auto-flag.
3. **Built the runnable Tier-1 (mechanical) + Tier-2 (dictionary) detector**, through three
   rounds of catching and fixing real false positives by actually running it against real text
   rather than trusting a plausible-looking regex:
   - First version of the mixed-script boundary-break rule fired 10,210 times, almost all on
     ordinary correct Pali loanwords — diacritics are just how Pali is transliterated, not a
     separate script; the heuristic's premise was wrong.
   - Second attempt auto-mined stems from the dictionary's "after" side — still caught a false
     positive from a messy free-text evidence string. Went back to the ~100 confirmed
     untranslated/noise evidence strings directly instead of trusting auto-derivation; nearly
     all of them trace to one stem, now a small, explicit, curated list with a maintenance note.
   - Even with that fix, an ordinary English plural of the stem was still flagged, because "any
     letter after the stem" included a legitimate trailing "s" — fixed by whitelisting
     legitimate suffixes instead of flagging any continuation.
   - The duplicate-adjacent-word rule also had one real false positive — a legitimate
     conjunction + demonstrative repetition in normal English — excluded by name after being
     caught in validation.
4. **Demonstration run**: applied the fixed detector to the current final text of all 43,805
   segments (the closest available proxy to "new, unreviewed text" given this DB login's
   scope) — found 436 still-broken compound-word artifacts beyond the 297 originally confirmed
   via the LLM pass (this scan covers every segment, not just the ones the full run classified),
   10,596 multi-word terminology-consistency flags, 183 duplicate-word hits (including a
   genuinely new find: a segment reading "he saw ten ten million monks," an uncaught duplicated-
   number typo), and 113 leftover US-spelling instances.

Also expanded the error pattern catalog with more real examples per the user's explicit
ask — several patterns went from 1-2 examples to 4-6, including a new cross-language
confirmation (the untranslated-Pali-proper-noun pattern also occurring in the Greek translation
layer) and the newly-found duplicated-number case.

**Core strategic takeaway, stated directly in the document**: a heuristic that sounds right
needs to be run against real text and checked by hand before being trusted — "generalizes well"
is measured (via the backtest), not assumed from a clean-looking regex.
