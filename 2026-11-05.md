## PaliVerse RAG — full-canon Root/Commentary/Sub-commentary migration scoped and test-run — 4 hours (16:30–20:30)

Source: `mini_rag/WORKLOG.MD`

Given the go-ahead to push the entire PaliVerse's text data — explicitly scoped to
Root (English + Pali) + Commentary (English + Pali) + Sub-commentary (Pali) only. No permission
yet for AI-generated explanations across the rest of the canon, so that layer is deliberately
left for later, not touched.

**Scoped the real loop before writing anything.** The chapter-scoping logic needs both the
source file and the chapter id, since one root text can span many chapters. Queried the real
structure: 173 total source files split by type — 59 root, 55 commentary, 37 sub-commentary, 22
Abhidhamma apparatus texts (excluded, outside the agreed scope) — giving **738 distinct
(file, chapter) pairs** across the 59 root texts, the real size of the loop, not "59 root texts"
as a flat list. Confirmed the existing commentary/sub-commentary linkage logic is already
generic per source file, nothing root-specific to generalize there.

**Real data extraction and load**: extracted the full Root+Commentary+Sub-commentary scope
(excluding the apparatus texts): **4,994,445 rows total**, ~1.15GB of CSV, across the two source
tables. Cleared the existing chapter-1-only companion snapshot before loading the full set (the
full extraction is a superset, avoiding stale chapter-1-only rows sitting alongside the real
data). One real slip: a typo in the first load attempt's log-redirect path meant the command
silently failed — caught immediately by checking the process wasn't actually running, fixed,
re-ran successfully. Both loads landed with exact row-count matches.

**New ingestion script built**: deliberately additive, not a rewrite of the existing one —
imports and reuses its actual building blocks so a single chapter's behavior stays identical to
what the existing script would do. Loops every (file, chapter) pair for root texts; deliberately
skips the synthetic info-tab layer and the glossary/knowledge-graph build entirely (no AI
content for the rest of the canon, per this session's agreed scope). Prunes stale chunks
per-chapter the same way the existing script does. Embeds once at the end across every root
touched in the run, not per-chapter, to avoid reloading the embedding client 738 times.

**One real bug found and fixed before the test run**: the chapter-listing function queried the
local source table's name instead of the name the Azure companion schema actually uses —
crashed with an undefined-table error on the first run; fixed, reran clean.

**Small-scope test run, real result, not yet the full run**: 2 root texts, 23 chapters, **8,696
chunks** (3,302 canonical + 3,208 commentary + 2,186 sub-commentary) built in 547.4s (~9.1 min).
Extrapolating that rate across all 59 roots: **~4.5 hours** just for chunk-building, before any
embedding — a real time budget to plan around, not yet attempted for the full canon. The
embedding pass afterward is separate again; since the real chapter-1 embedding rate was cheap
and full-canon token volume was projected earlier today at ~16.1M tokens, embedding cost itself
stays cheap — the bottleneck is wall-clock chunk-building time, not dollars.

**Not yet done**: the actual full 738-chapter run (only the 2-root test has run so far);
embedding the full canon once chunks are built; re-verifying real final storage size against
the ~5.6GB projection.
