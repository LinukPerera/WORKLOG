## Agent Unit Explanations — Stage 8 real generation, analytics, client deliverable, cost correction, architecture diagram — 5 hours (10:30–15:30)

Source: `agent-unit-explanations/WORKLOG.MD`

**Stage 8: full 149-unit generation, real.** Submitted all 149 real prompts to the Opus-class
model via the Batch API, per the user's go-ahead (cost was shown and confirmed first —
$3.53/$7.06 projected — before this ran, per the project's own non-negotiable rule 6). 149/149
succeeded, 0 failed, 334.4s submit-to-finish. A 2-request smoke test beforehand caught a real
bug before committing to the full batch: the model's default adaptive thinking puts a thinking
block first in the response content list, so grabbing the first content item directly would
have crashed on any unit that actually thought — fixed to find the real text block by type.

**Stage 9: analytics**, reusing this project's own established tooling (the same fluency
toolkit from the earlier S0101 translation experiment — GPT-2 perplexity, Flesch readability,
Claude Haiku 1-10 fluency score) plus mechanical checks specific to this pipeline (all 9
required sections present, no internal source/tool name leaked into the reader-facing text).
Result: 149/149 pass every mechanical check; avg fluency 9.0/10, avg 1,690 words/unit.

**Client deliverable.** Combined all 149 explanations into one plain text file. First version
included each unit's verbatim root text (Pali + English) above its explanation; the user asked
for explanations only, so root text was dropped from the combined file (still lives separately
elsewhere, nothing lost).

**Cost reporting, two real rounds of correction — both caught by the user asking to confirm the
numbers, not found proactively:**
1. First pass reported $10.2069 for Stage 8. The user asked to confirm it; checking the
   pricing page's own wording ("cache multipliers... stack with the Batch API discount") found
   the script had applied the live-tier cache-read price to a batch request's cache-read tokens
   instead of the batch-adjusted price. Corrected to $10.1428.
2. Second pass, the user pointed out cache write showed $0 and an earlier Haiku-based
   entity-extraction stage's cost wasn't in the table at all. Investigating properly surfaced
   two real, previously untracked costs: 149 Haiku entity-extraction calls made during
   yesterday's prompt build (never logged — only the parsed entity list was cached, not usage;
   reconstructed via the free token-counting endpoint, real cost $1.35) and a 2-request Batch
   API smoke test run before the real batch, whose output was discarded and both units
   regenerated for real ($0.29). Grand total corrected $10.51 → **$12.15** (~8% of the $150
   ceiling).

**A real quality finding, surfaced by the same cost investigation, not by design**:
reconstructing the entity-extraction stage's real cost required replaying every one of the 149
calls, which showed **two units both hit the output-token cap** during the original run —
Haiku's JSON response was truncated mid-string and failed to parse. The earlier fix (don't
cache a parse failure as a real "0 entities" result) correctly stopped that from poisoning
future reruns, but the fallback still silently returned an empty list rather than retrying —
**both units' explanations were generated with zero entity/term grounding.** Flagged to the
user; not yet retried (their call: cheap to fix, a few cents and a minute, versus leaving it and
disclosing the gap).

**Architecture diagram.** Built a Mermaid flowchart covering all 10 pipeline stages end to end,
colour-coded to highlight what's actually non-trivial about the design: the 3-tier entity/term
resolution fallback (dictionary → mechanical → semantic), the sequential introduction ledger
(stateful across all 149 units), and the no-spoiler boundary enforced at retrieval rather than
left to the model to self-censor. Verified it renders cleanly before pushing (a local PNG
preview looked textless — confirmed via the raw SVG that the labels are real, just rendered in
a way the local preview tool doesn't support but GitHub's renderer does). Also pushed a
user-provided architecture diagram image.
